首套组合在设置上下限内二分建立初始纪录。后续在当前纪录粗筛100场，只有单侧95%精确上界低于目标减5个百分点才淘汰。每等级默认1000场，达标升1级；首批目标以下5个百分点以内仅补测一次1000场，合并后目标以下2个百分点以内则停止并保留（目标70%时，65%起补测，68%起容差保留，70%达标）。刷新纪录另用独立1000场确认，失败不反复重抽。

最终冻结最高纪录，所有同级达标与容差候选展开合法技能顺序，每种独立5000场；按实际样本胜率和胜场平均耗时显示双榜各至多五种不同技能组合：按光环与无序主动技能集合去重，各榜选该组最优装备与顺序，全部顺序结果可导出。速度榜仅纳入最终达标者。最终样本未达标如实标记，不回退等级，也不再升阶。

粗筛95%仅针对单次判断，整个搜索不声称全任务置信认证或真实最优。战斗内核、怪物成长和固定半冷却规则沿用043。有限样本搜索依赖胜率随等级不升的工作假设。

候选窗口有界，淘汰组合与完成缓存及时清理；审计保存阶段汇总、最终顺序结果及淘汰候选的怪物、配装、首轮/补测/合并胜率与耗时和淘汰原因，不提供逐场回放。阶段模式不训练或追加学习档案，旧档案保留。暂停和恢复沿用已保存的新样本，044断点不能跨版本恢复。

这是纯静态网站，无需构建、后端、登录或遥测；数据和计算留在使用者浏览器。

## 发布步骤

1. 在 GitHub 新建一个 **Public** 仓库。
2. 把本发布包根目录中的全部文件上传到仓库 `main` 分支根目录。必须让 `index.html` 直接位于仓库根目录，不要再套一层同名文件夹。
3. 打开仓库 **Settings → Pages**。
4. 在 **Build and deployment** 中把 **Source** 设为 **Deploy from a branch**，分支选择 `main`，目录选择 `/(root)`，保存。
5. 等待 GitHub 完成部署。项目站点通常是 `https://你的用户名.github.io/仓库名/`。

GitHub 官方说明：<https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site>

## 使用方式

- 网页版不会自动连接 Windows 本机启动器，请在页面中手动选择 `init_character_data.json` 和 `init_client_data_v*.json`。
- 公共数据桥接脚本可在游戏页捕获这两份文件；自动推送仅对 Windows 本机版有效。
- 模拟完全在访问者浏览器和 CPU 中运行。站点没有后端、登录、数据库、遥测或文件上传接口。

## 不要上传的内容

不要上传开发项目目录、真实角色 JSON、测试夹具、`.git`、`.openai`、`.env*`、`node_modules`、构建缓存、研究日志或 Windows 构建工作目录。只上传本发布包内的文件。

## 更新

更新时，用新发布包中的 `index.html`、`styles.css`、`assets`、`data`、`engine`、`js` 覆盖仓库中的旧版本；保留 `.nojekyll`。游戏更新后，使用者仍应自行加载与角色数据同版本的客户端 JSON。
